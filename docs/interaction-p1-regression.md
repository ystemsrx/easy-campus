## 日程滑动实现

使用 Skyline 原生 swiper，窗口内三个星期的 21 个日期按真实日历顺序排列，native current 决定选中日期。滑动和点选期间不替换面板日期，也不通过循环槽位猜测前进或后退。仅在窗口端点完成滚动后无动画调整窗口，保持页面数量有界；cache-extent 为 1。支持周日进入下周一、周一返回上周日，以及跨月、跨年和闰日。

顶部星期条和选中标记由 Worklet 的 onscrollstart / onscrollupdate / onscrollend 驱动。位移基线在 UI 线程的 onscrollend 内提交，不再等待逻辑线程 animationfinish 重置。顶部使用绝对日历日坐标，与原生窗口索引解耦；扩展日期窗口不会改变可见星期的位置，只有屏外星期会更换数据。日面板与星期条分别测量实际宽度，transform 使用 px。

动画绑定同时等待页面 onReady 和日期列表的 setData 渲染完成。窗口初始化先关闭原生动画，因此 onReady 可能早于日期节点出现；只在 onReady 绑定会选中空列表，之后数字仅靠选中 class 突变，选择器则停留在初始位置。现在仅在节点存在时绑定一次，固定 slot/weekday key 保留绑定；绑定完成前隐藏尚未定位的星期条，避免三周重叠一闪。样式回调直接捕获位置和宽度 SharedValue，并以 sync 刷新跟随同帧滑动。WXML 不再写入 transform，选中 class 不再改写透明度；宽度由七等分布局负责，测量不再触发 style 的 setData 更新。

每帧只更新 SharedValue，不经 setData。点击星期选择真实日期对应的原生索引，不把目标日期塞进相邻槽位；切换中的新点击保留最后一次意图。普通切换 240ms；减少动态效果时使用无动画定位，不依赖零时长动画的结束事件。窗口调整期间忽略原生内部定位产生的动效回调，旧手势回调通过序号失效。日内容不叠加入场动画。

一段滑动只提交一次位移。`onscrollend` 关闭当前滑动后，后续尾帧和重复 end 不再更新选择器或数字颜色，直到下一次 scroll start。窗口重定位分三次完成渲染：先关闭 scroll-with-animation 并把 duration 设为 0，再修改日期和 current，最后恢复动画；整个过程保持 Worklet 回调关闭，被新定位取代的旧渲染回调也按序号失效。

平台依据：[微信官方 Tab 指示条示例](https://github.com/wechat-miniprogram/awesome-skyline/tree/main/examples/tab-indicator)、[微信官方 swiper 能力参考](https://github.com/wechat-miniprogram/skyline-skills/blob/master/skills/skyline-components/references/layout/swiper.md)。项目已启用 compileWorklet，基础库配置为 3.17.0。

日期数字使用固定对齐的两层文字，由 Worklet 按选择器的同一个绝对日期坐标交叉渐变。相邻日期之间拖动一半时，旧、新日期各显示一半选中色；回拖沿相同进度恢复，取消后回到原色。不等待 selectedDate 落定，也不另启动 CSS 动画。点击日期时随原生滑动逐帧变色，减少动态效果时随原生定位同步结束。极简主题使用各自的正文色和强调色上文字色。这里不使用 Skyline 不支持的 `color` 动画，见[微信官方过渡属性说明](https://github.com/wechat-miniprogram/skyline-skills/blob/master/skills/skyline-wxss/references/animation.md)。

颜色回归检查直接执行动画样式回调，验证 25%、50%、75% 拖动及回拖的两层透明度，包含周日/周一交界、同周切换、程序点选和 JS 回调尚未送达的情况。每次日期落定还验证选中数字的透明度终值。

新增绑定生命周期回归：分别模拟 onReady 先于日期渲染、日期渲染先于 onReady；空列表不接受节点动画绑定。通过 SharedValue 订阅检查实际应用的样式，不手动执行 updater，验证慢拖、回拖时选择器与数字同步变化，以及切换页签、调整日期窗口后不重复绑定。将新回归运行于修复前控制器，会得到 0 个绑定而非预期 48 个；当前控制器通过。该替身验证生命周期与状态依赖，仍不模拟微信的 Worklet 编译器或 Skyline 设备渲染。

## 验证

课程助手新增的收藏缓存遍历曾触发开发者工具 2.02.2608060 自带 Babel 的类型推断错误：对被条件表达式重新赋值的 `catalogCourses` 使用 `for...of`，会混合 TS 和 Flow 类型节点并阻断页面脚本生成。改用等价的数组 `forEach` 后，同版编译器已能生成课程助手模块。`tsc` 和控制器运行测试使用的 TypeScript 转译器无法覆盖这条编译链。

新增 `npm run check:devtools -- "<微信开发者工具可执行文件路径>"`（也可设置 `WECHAT_DEVTOOLS_EXECUTABLE`），在工具自带的 Electron 中直接调用实际 Babel/Worklet 编译器，按项目设置编译全部运行时 TypeScript 文件并检查输出的 JavaScript 语法；不写入构建产物，不启动页面或访问服务。此检查需要本机安装开发者工具，独立于 `npm run check` 执行。同版工具已成功编译全部 103 个 TypeScript 文件，包含日程 Worklet；修复前课程助手可复现用户日志中的同一错误。

付款确认区域使用常驻的零高度容器，内容挂载并完成渲染后测量实际高度，以 260ms 的 height 过渡推开下方原有套餐列表，内容同时淡入。结束时先收起高度并淡出，260ms 后才卸载；退出阶段保留原加载文案和图形。快速完成、收起中重试、待确认状态及视口变化均通过新的测量版本忽略旧回调；减少动态效果时直接定位。这里按产品要求改变一个容器的实际布局高度，不逐个移动或压缩套餐卡片，不逐帧 setData；height 是 [Skyline 支持的过渡属性](https://github.com/wechat-miniprogram/skyline-skills/blob/master/skills/skyline-wxss/references/animation.md)。支付状态机仍按原逻辑运行，视觉展开不阻塞请求和结果确认。

付款区域回归分别排队执行渲染、尺寸测量及卸载定时器，覆盖先挂载再展开、保留内容收起、快速反向、待确认高度、窄屏重测、过期测量、减少动态效果及卸载后的回调。仅验证状态与渲染更新顺序，未模拟 Skyline 原生过渡帧率。

上一版测试把 Worklet 到 JS 的回调和 setData 渲染回调都当作同步执行，未覆盖线程延迟及真实原生索引，不能证明滑动正确。该测试缺口已纠正。

`npm run check:interactions` 执行真实 TypeScript 控制器和渲染函数，使用内存存储、固定数据及请求替身，不调用生产服务。现在分别排队执行 Worklet 到 JS 的回调和渲染完成回调；覆盖 240 次连续切日、JS 延迟期间再次滑动、每次落定后的日期/星期/指示器坐标一致性、窗口调整回调尚未完成时的顶部坐标、反向、取消、快速跨日点选后继续滑动、窄视口测量、跨年、闰日、减少动态效果及滑动中保存。已纳入 `npm run check`。
