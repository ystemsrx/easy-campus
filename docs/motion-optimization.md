# 动效优化 · 2026-09-07

根据前端交互分析报告第三节和第二批实施建议，收敛高频动效，补齐退出生命周期与减少动态效果。沿用 Skyline 原生组件、WXSS 过渡和既有主题；没有新增动画库、后端接口或逐帧逻辑线程更新。

## 实现约定

`miniprogram/motion.wxss` 定义抽屉共同的位移、透明度和命中规则；页面与独立组件使用相同的类。`miniprogram/utils/motion.ts` 定义语义时长与呈现生命周期。通用抽屉、空教室结果/节次抽屉、通过率课程选择共用生命周期；伙伴抽屉保留常驻内容及既有滚动结构，使用共同样式。长列表仍在各自 WXML 中，与滚动容器同层。

过渡使用现有节点的 transform/opacity，可从当前视觉状态重新定向。挂载后的首次显示等待渲染提交；退出计时从关闭状态渲染后开始。每个实例及弹层独立标识当前操作，取消不依靠“此刻是否已打开”的单一判断。共用提示保留约三秒阅读时间，新的提示更新文案并延长显示。

日程已有的真实日期 swiper、Worklet 选择器和数字颜色联动继续沿用。付款确认区域按此前明确要求保留 260ms 的实测高度过渡，用于推开下方套餐；它是有意保留的布局动画，本轮不将其改为覆盖层或整块缩放。

平台依据：[微信 Skyline 动画属性参考](https://github.com/wechat-miniprogram/skyline-skills/blob/master/skills/skyline-wxss/references/animation.md)、[微信 swiper 能力参考](https://github.com/wechat-miniprogram/skyline-skills/blob/master/skills/skyline-components/references/layout/swiper.md)。不依赖 Skyline 不支持的文字 color 插值，也不引入浏览器 DOM/WAAPI 方案。

## 验证和边界

`npm run check:motion` 纳入完整检查。测试分开排队处理渲染提交、nextTick 和定时器，执行实际组件控制器及首页完成逻辑，覆盖：

- 显示尚未提交就关闭、退出中重新打开、旧退出回调迟到、多个实例独立、卸载后回调失效。
- 减少动态效果的 120ms 卸载，排序立即生效，重复提示和页面隐藏清理。
- 底栏重复导航、失败恢复以及旧失败不能覆盖已显示页面。
- 同时完成两项、同项防重、按最新记录补位、页面隐藏时结算以及减少动态效果即时完成。
- 注册页面的组件偏好传递、原生 swiper 参数、无列表错峰、共同样式与逻辑时长一致。

验证通过：完整 `npm run check`，Skyline WXSS 检查 0 个错误；开发者工具 2.02.2608060 实际 Babel/Worklet 编译全部 106 个 TypeScript 文件。主包 1,700,676 字节，功能分包 1,090,289 字节。测试替身与脚本编译均不能证明设备视觉流畅度。

动效视觉验收结论：**Block（仍需 Skyline 真机验收）**。这不是新增审批要求。必须实机检查窄屏、短屏、大字号、深浅色与三种主题下的首次打开、快速开关、连续待办完成、卡片展开、消息/课表滑动，以及减少动态效果时的命中与退出。尚未获得真机帧率数据，不宣称性能指标已达标。

原报告中伙伴离屏/输入/滑动时的精细调度和性能采样属于第四批工作，本轮没有重写伙伴引擎。待办撤销入口和其他非动效功能也不在本轮实现范围。
